# Project130 device-model rules

## Guest-visible devices

The x86 guest sees software models. The initial compatibility target is a deliberately scoped 8086 Real Mode machine, not a claim of complete IBM PC/XT compatibility.

Candidate devices to specify and implement in stages:

- PIC 8259-compatible interrupt controller;
- PIT 8253/8254-compatible timer;
- keyboard controller/input path;
- system board/PPI behavior as required by selected BIOS/software;
- VGA-compatible register, memory and scanout model;
- RTC and block-storage services mediated by the ATM host.

## Strict separation

1. x86 IN/OUT accesses only the guest virtual I/O bus.
2. Guest IRQ state is maintained by the emulated interrupt controller.
3. Timer events are generated by the emulator's time source, not by direct access to an ATM timer port.
4. Keyboard, RTC and storage operations requiring physical hardware are submitted to the ATM host using DMA messages.
5. NeoGS does not access ATM hardware ports or physical devices directly.
6. A guest DMA controller, if required, is a software model operating on guest memory; it is not the NeoGS DMA engine.

## Compatibility discipline

Implement only the documented behavior needed by the selected BIOS and test software. Record unknown reads, writes and unsupported commands in diagnostics. Do not return arbitrary success values for unimplemented device behavior.
